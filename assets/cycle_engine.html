MT5 AGENT

CYCLE ENGINE

Claude reads market structure and proposes a trade. A deterministic risk engine — risk.py, zero AI — independently validates and sizes it before anything reaches the broker. The model never places an order. It never sets the size.

One decision cycle — seven stages, in call order
  1. 01

    mt5_client.py

    MT5 Market Data

    Pulls OHLCV straight from the running terminal over local IPC — no second data vendor to drift out of sync. bars() always drops the forming candle: indicator values stay fixed within a bar and a decision replays identically later. Reads like an off-by-one. Isn't one.

    2. raw bars →
  2. 02

    features.py

    Feature Snapshot

    Normalises every timeframe into a plain-Python summary — the f() helper strips numpy scalars before anything reaches a prompt. Hold-confidence is computed here, deterministically, instead of trusting the model's guess. bars_since_break and retracement_pct mean a retest no longer needs a same-bar contradiction to register.

    3. snapshot (native types) →
  3. 03
    Only step that guesses

    decision.py

    Claude Decision

    Reads the snapshot and proposes hold or open — direction, entry, stop, target, confidence, and a risk_fraction from 0–1 of a configured maximum. It never states a lot size and never touches order_send. Timeout, missing data, or an unparseable reply all fail closed to hold.

    4. Decision{} →
  4. GATE

    risk.py

    Risk Engine

    "Contains no AI. It is the gate between what the model proposes and what actually reaches the broker."

    • Session window + spread ceiling
    • Daily loss limit + loss cooldown
    • Max open positions on this magic number
    • Stop-loss present, on the correct side
    • Minimum reward:risk enforced
    • Sized by tick value, never pips
    • Volume rounds DOWN to volume_step
    • Sub-minimum size refused, never bumped up
    • Stop modifications may only tighten
    • Every rejection logged with its reason
    5. RiskVerdict{} →
  5. 05

    execution.py

    Execution

    Sends the sized order tagged with a magic_number, so every later query can prove which positions are this bot's. Filling mode is read from the broker's own bitmask, not assumed. Currently held behind dry_run: true — nothing reaches the market yet.

    6. order / ticket →
  6. 06

    journal.py

    Journal

    Every cycle is written to logs/cycles_*.jsonl — hold, rejection, or fill alike — with its reasoning intact. Nothing about a quiet cycle is discarded.

    7. cycles_*.jsonl →
  7. 07

    dashboard.py · analytics.py

    Dashboard Feedback

    Reconstructs cost from Sonnet 5 token pricing, latency, hold rate, confidence spread, and rejection reasons from the journal — and warns when the sample is under 30 cycles. Feeds the next phase: calibrating confidence against realised outcomes.

↺ Windows Task Scheduler re-arms the cycle every 15 minutes, 09:00–22:00 Mon–Fri — matching the M15 decision timeframe and the session gate in risk.py.

Always-On Guardrails

Not style preferences — each one blocks a specific way this system can lose money.

  • Model never calls order_send
  • Model never sets volume — only risk_fraction
  • Volume rounds DOWN, never to nearest
  • Sub-minimum size refused, never bumped up
  • Stops may only tighten — no exceptions
  • bars() drops the forming candle
  • Sized by tick value, never pips
  • Every order carries a magic_number
  • Secrets live in .env, never in code
  • A gate is never weakened to pass a test
